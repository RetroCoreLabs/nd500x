# ND-5000 '87 extension: what is still needed

Date: 2026-11-02. Scope: the 25 instructions labelled "('87 extension)" in the ND-500 Reference Manual ND-05.009.4 (June 1987). Plan and measured results: `docs/ND5000-87-EXTENSION-PLAN.md`. Manual text per instruction: `docs/ND5000-87-EXTENSION-INSTRUCTIONS.md`.

Each item says what is unknown, what was already tried, and what would settle it. Nothing here can be settled from the manual, the microcode and the vendor assembler we have. Every item needs either a person who knows the ND-5000 design, a real ND-5000 machine, or a vendor program that uses the instruction.

## 1. PLCCN: two operands or three

- Manual (section 15.15, page 268): `W PLCCN <source/r/W>,<destination/w/W>`, two operands.
- June 1986 PLANC-500 assembler, version G (measured, run under nd500x): accepts PLCCN (opcode 0xFFFD) only with exactly three general operands. Two gives MISSING OPERAND(S), four gives TOO MANY.
- Searched: the vendor binaries we have. No real PLCCN use found. Raw 0xFFFD hits were parts of constants.
- Needed: a program or listing from the ND-5000 era that uses PLCCN (PLANC or assembler source with the generated bytes), or the designer's statement of the operand count.
- Effect now: the nd500x handler follows the manual (2 operands). The five `Ext87_Plccn_*` corpus cases assert only N and Z.

## 2. PLCCN: descriptor layout and the A word

- Manual wording ("a + 1") and the microcode (a + 4 * l) disagree on what is written as the address word.
- Needed: the PLANC descriptor layout (byte offsets of a, l, u) and the ND-500 descriptor layout the result must have.

## 3. NCPLC: the N = 0 case

- Manual does not say what happens for an empty array.
- Needed: microcode trace of NCPLC with N = 0 on an ND-5000, or the designer's answer.

## 4. ENTIER: overflow value

- Manual gives no result for a value too large for a word. The nd500x handler clamps and sets O (inferred, not from the manual).
- Needed: the result the ND-5000 microcode or hardware produces for overflow, and whether O is set.

## 5. TOSSP

- A quirk in the microcode path is not explained by the manual.
- Needed: the designer's description of "special load of TOS", or a program that uses it.

## 6. SEND and RECVE

- Operand W2 to W4 forms, the message tables and the port tables are not described in the manual.
- Needed: the NUCLEUS port and hole documentation, or a program that sends and receives.

## 7. RHOLE and WHOLE

- RHOLE (0xFE9E) has no routine in the ND-5000 microcode used for study (MICRO-5800-B30). WHOLE exists in the manual only.
- Needed: which microcode version has RHOLE, or confirmation that it is not implemented in hardware.

## 8. AMODB

- The manual gives 0xFFBC to 0xFFC7. In MICRO-5800-B30 these opcodes lead to the illegal-instruction stub.
- Needed: confirmation that AMODB is manual-only, or the microcode version that has it.

## 9. DDIRT encoding

- Manual: 0xFFFA. NDIX-C assembler tables: 0xFE1E. Both reach the microcode routine DCDUMP, and nd500x and the C# emulator now accept both.
- Needed: which one the ND-5000 hardware really uses, so the other can be marked as an alias.

## 10. RIOM, RPHS and WPHS operands

- The vendor assembler accepts a constant as RIOM operand 2, while the manual says write access. For RPHS and WPHS the template is 0x0001FFE8 in one source and 0x0003FFE8 in another (plan items 9 and 10).
- Needed: the designer's rule, or generated bytes from a vendor program.

## 11. Which instructions are privileged

- The manual marks CLINIT, SCNTXT, LCNTXT, REXT, WEXT, RPHS, WPHS and CAD as privileged. For the other 17 it says nothing, which is not the same as allowed in user mode. LREGBL has a partial rule: in non-privileged mode it cannot change ST2, PS, CED, CAD, CTE, MTE and TEMM.
- Needed: the designer's full list, or a user-mode run of each instruction on a real ND-5000.

## Not blocking

- The C# generator skips the '87 instructions on purpose (`Extension1987Mnemonics` in `Emulated.Tests.ND500/Instructions/TestND500_GenerateComprehensiveTests.cs` in the RetroCore repo). That rule is Ronny's and was left unchanged.
